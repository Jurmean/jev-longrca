# Adaptive JEV-RCTA v2

协议为 `jev-rcta-adaptive-v2`；入口为 `scripts/evaluate_jev_rcta_adaptive_v2.py`。
旧版 `jev-rcta-adaptive-v1` 留作复现，停止的 Mini 目录不恢复、不混入新版结果。

## 为什么重构

2026-09-24 的 v1 Mini 在用户要求停止时完成 45/200 条，全部弃答。记录了 1,554 次成功响应、13,156,546 输入 tokens、560,167 输出 tokens，包含连接题和未完成样本的中间请求；不是完整 Mini 分数或账户账单。

前 40 条的诊断显示，约 75% 的输入 tokens 花在初始全轨迹扫描。搜索反复打开候选，却很少完成同一候选的上游、修复和反证检查。外层预算异常还会直接跳过最终判定。最后，大候选集合无法在累计概率阈值下缩减时，分组决赛直接弃答。

这些是调度与预算设计缺陷，不能据此断言原题设计有问题或 JEV 没有判断能力。

## 新流程

**本地无损索引 → 分层目录导航 → 按需读取 segment 并打标签 → 集中核验候选 → 保留预算做最终选择 → 独立证据核验。**

1. **目录导航替代付费全扫描。** 本地建立所有 segment 的树形目录。目录展示步骤范围、关键词标签和带字节偏移及哈希的原文摘录，不生成摘要。JEV 回答下一步最值得读取哪个区域，再逐层深入到原文段。树的分叉数是单次问题的大小上限，不是固定保留 top-k 的候选数。
2. **概率控制优先级，未选分支保留。** 同一个问题内按完整概率排序，累计质量集合优先进入队列，其他分支仍可回溯。`unknown` 的概率不被移除或重新归一化；此时具体分支只作为探索方向，不被声称为可信证据。不同问题的概率不直接相乘，也不作为可比较的全局后验。
3. **先闭合当前候选。** 一个候选依次经历本步检查、上游原因、后续修复和反证检查，再打开其他候选；有原文支持的更早原因可接管当前分支。每类关系先做一次有界检索，未知结果和未读页数保留在 `check_coverage`，不把“问过了”视为“已证实”。只有模型明确要求更多本步证据时才追加本步展开。
4. **给最终判断预留预算。** 搜索同时受调用数、累计请求字节和估计输入 tokens 约束，并预留最后两次调用。预算触发后进入最终判定。实际输入 token 用量随响应校正估计；服务端用量在响应后才能知道，因此 token 上限不是绝对账单保证。
5. **紧凑候选卡替代不能收敛的分组决赛。** 最后比较所有已经检查、尚未被否定的候选，卡片包含标签和原文摘录。根据请求空间缩短展示摘录，候选 ID 不因概率分布平坦而被强制删掉。独立核验时再读取所选候选的完整原文片段和补充证据。
6. **预测与核验状态分开。** `predicted_step/role` 是当前最佳点预测；`verified_step/role` 只记录达到严格证据条件的子集。低置信度可以产生 `best_effort` 预测，但不能记为 `supported`。独立核验明确否定、没有已检查的可用候选或最终模型选 `unknown/outside` 时仍可弃答。

`supported` 指已检索原文支持该归因，仍不是遍历全轨迹后的全局因果证明。模型可能在未读区域遗漏更早原因；输出的 `coverage` 明确记录实际读取范围和待查分支。

## 默认预算

| 项目 | v1 | v2 |
|---|---:|---:|
| 单条逻辑调用上限 | 64 | 24 |
| 累计输入 token 上限 | 300,000 | 80,000 |
| 累计请求字节上限 | 1,600,000 | 240,000 |
| 搜索动作上限 | 24 | 12 |
| segment 字节上限 | 32,000 | 12,000 |
| 单次请求字节上限 | 62,000 | 26,000 |
| 最终单次请求字节上限 | 共用上限 | 20,000 |
| 最终预留 | 不完整 | 2 次调用、40,000 请求字节、24,000 输入 tokens |

实际调用数取决于分支和预算；重试可能增加网络尝试。上述数字是配置限制，不能当作实测节省比例。质量阈值仍是未校准的 0.9 集合质量和 0.8 强判断阈值。

## 输出含义与公平比较

| 状态 | `predicted_step` | `verified_step` | 含义 |
|---|---|---|---|
| `best_effort` | 可以有值 | null | 已作出点预测，但证据或置信度不足 |
| `supported` | 有值 | 有值 | 满足当前检索范围内的严格核验条件 |
| `abstained` | null | null | 没有可用预测或存在明确反证 |

统计必须同时报告点预测准确率、覆盖率、严格核验子集的覆盖与准确率，以及 token 和调用数。
v2 的点预测分数不能与 v1 严格弃答分数直接比较后就宣称推理提升。相同样本、输出策略和预算下的对照仍需真实实验。
改变最终输出策略也不等于找到了更好的根因；架构改动的实际收益尚须验证。

## 运行

离线检查不读密钥、不请求 API：

```bash
python3 -m unittest discover -s tests -p 'test_rcta_adaptive_v2.py' -v
python3 scripts/evaluate_jev_rcta_adaptive_v2.py --demo --output results/jev_rcta_adaptive_v2_demo_20260924
python3 scripts/evaluate_jev_rcta_adaptive_v2.py --audit-only --mini --output results/jev_rcta_adaptive_v2_audit_20260924
```

合成演示使用预设回复，只验证调度与证据指针，不能证明 JEV 准确率。离线 Mini 审计检查原文无损、所有 segment 均可从树根到达；不代表模型读过全部原文。

仅显式 `--live` 调用 API：默认先连通性测试，再运行每个来源最短的一条，共五条。沿用私有环境配置和精确请求缓存，额度不足立刻停止。

```bash
python3 scripts/evaluate_jev_rcta_adaptive_v2.py --live --output results/jev_rcta_adaptive_v2_smoke_20260924
```

如果之后显式选择 `--live --mini`，也是先完成五来源预检；五条全部没有点预测时，自动以 `stopped_no_usable_predictions` 停止，不扩展剩余样本。这个门槛不读取参考答案，不会在线修改阈值；有输出并不等于准确率达标。

配置、代码、模型、端点和数据版本冻结到各自运行目录。`user_stop.json` 和 `balance_stop.json` 阻止自动恢复。不同协议或修改后的代码须使用新目录。

## 文件

- `scripts/rcta_directory.py`：本地树与可核对的原文摘录。
- `scripts/jev_rcta_adaptive_v2.py`：导航、候选集中核验、预算预留、双层输出。
- `scripts/evaluate_jev_rcta_adaptive_v2.py`：离线与真实运行、连通性检查、预检门槛、统计。
- `tests/test_rcta_adaptive_v2.py`：预算边界、长轨迹、未知分支、输出语义、参考答案隔离和精确重放。

文献依据沿用 [Adaptive RCTA 的研究记录](../reports/jev_rcta_literature_design_20260924.md)。这里是工程实现，未复现论文的训练过程或理论保证。

## 本次验证结果

用户重新允许 API 测试后，运行了五来源各一条短样本和一条 645 步长轨迹，共六条；未重启整套 Mini。

- 5/6 条给出点预测，1/6 条弃答；严格证据支持仍为 0/6。
- 根因 Exact 为 2/6，±5 为 3/6，责任角色正确为 1/6。
- 相同六条样本的轨迹调用从 v1 的 161 次降至 91 次，输入从 996,459 降至 324,485 tokens，减少约 67.4%。
- 本次实际成功 API 请求共 93 次，包含两次连接题；输入 325,143 tokens，输出 14,014 tokens，无传输重试。
- 长轨迹从旧版 27 次调用、307,258 输入 tokens 后弃答，变为 14 次调用、55,631 输入 tokens 后输出点预测；该预测仍偏离参考根因 91 步。

这些结果支持“降低调用成本、改善输出可用性”，尚不支持“根因定位准确率提升”。同样六条上的历史 JEV baseline Exact 也是 2/6，±5 为 4/6，角色正确为 3/6；新版仍存在候选定位与角色判断问题。样本少且按长度选择，不能当作完整 Mini 结论。

离线共 88 项测试：83 项通过、5 项因 Laya 独立推理环境未启用跳过；新增 v2 测试 15 项全部通过。200 条 Mini 原文完整性与目录可达性审计通过。
