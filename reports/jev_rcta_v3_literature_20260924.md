# 将相关论文方法落到 Adaptive JEV-RCTA v3

日期：2026-09-24。查阅原始论文、正式论文集及作者仓库。下述实现是适配 JEV Choice 的工程方法；不把原论文的实验增益、训练能力或理论保证移植为我们的结论。

## 从失败记录出发

v2 的六条开发样本中，根因 Exact 2/6、角色正确 1/6，严格核验 0/6。长样本只有 2/167 个 segment 被整段读取，最终步骤偏离参考 91 步。源码还暴露了三个流程问题：

1. 目录树先走一个局部区域，后续取证仍很容易停留在那里；原始任务与最终现象没有形成相互补充的全局检索视角。
2. 模型提出缺少本步原文或上游要求后，控制器仍大体按固定顺序执行其他检查。上游假设的置信度未达 0.8 时，甚至不会把已引用的更早原文加入追溯。
3. 根因步骤与责任角色在同一次请求里独立回答，角色题无法以该轮刚选出的根因作条件；所谓“独立核验”还携带先前标签，存在锚定风险。

这些观察用于定位工程缺陷，不用于对 Mini 的参考步骤、角色或理由编写特判。

## v3 的实际流程

**无损原文索引 → 多查询本地检索 → RRF 融合、MMR 去冗余 → JEV 选择证据锚点与候选 → 按缺失事实选择下一题并更新检索 → 根因点预测 → 以该步骤为条件判断角色并核验原文。**

- 所有候选都来自当前轨迹的原文，不让模型编造步骤或引用。摘录有自身的 UTF-8 偏移和哈希；读候选时取回完整片段。
- 全局检索在本地进行，不调用额外 embedding 服务。检索记录保存查询来源指针、候选视图和所需证据类型，便于分析是“没有取到”还是“取到但判断错”。
- 全局 Choice 在同一道问题里按完整概率形成自适应集合。跨检索查询使用名次融合，跨 Choice 不相乘概率。
- `upstream` 只要在保留集合中、相对 `local` 更有支持且引用确实指向更早原文，就可进入待查队列；`verified_causal_edge` 仍为 false。发现候选与确认因果使用不同条件。
- 不反复穷尽每个候选的所有检索页。每次集中做有针对性的补证，然后回到全局视角寻找竞争解释。
- `best_effort` 与 `supported` 分开。v3 的严格核验检查错误在目标处引入、同一错误仍持续、直接原文引用和选择置信度；未知仍是未知。该判据与 v2 的“四个历史检查都达阈值”不同，严格通过率不得直接归因于检索改进。

## 实现与可拆分验证

| 文件 | 作用 |
|---|---|
| `scripts/rcta_retrieval.py` | BM25、RRF、MMR、查询相关的原文摘录 |
| `scripts/jev_rcta_adaptive_v3.py` | 多轮反馈、问题依赖、上游假设、分轮归因和核验 |
| `scripts/evaluate_jev_rcta_adaptive_v3.py` | 独立协议入口，复用连接预检、缓存和额度停止 |
| `tests/test_rcta_adaptive_v3.py` | 方法与工程边界测试 |

保持 v2 的总预算：每条最多 24 次逻辑调用、80,000 输入 tokens、240,000 请求字节；最后两次调用及相应预算仍预留。token 估计依然不是服务端账单的硬保证。

三个开关均进入冻结配置，可做后续消融：

- `global_retrieval=0`：恢复目录导航，检验全局检索的贡献。
- `iterative_queries=0`：去掉原文锚点与需求标签对查询的反馈。
- `factored_verification=0`：恢复 v2 的同轮角色归因与带标签核验。

开关验证只证明模块可以拆分。没有实际运行相应对照时，不能声称某篇论文或某个组件带来了测得的增益。

## 评测原则

先做无网络测试和原文完整性检查，再使用已获授权的小样本 API 验证。先连接题，再五个来源各一条；若可运行，再补前轮那条长轨迹。保持代码和阈值冻结，遇到额度不足立即停止，不自动重启已停止的 Mini。

这些反复查看过的六条属于开发诊断集，不是未见测试集。必须报告同样本 v2 对照、步骤与角色准确率、严格核验覆盖、实际用量以及失败案例，不能只报告弃答下降。全量 Mini 或组件因果贡献仍需单独的、预先确定的对照实验。

## 实测后的修正与当前状态

冻结的 v3 在同样六条上 Exact 1/6、±5 2/6、角色正确 2/6，点预测覆盖 4/6，严格核验 0/6；v2 分别为 Exact 2/6、±5 3/6、角色正确 1/6。v3 用 80 次样本调用、330,308 输入 tokens，v2 用 91 次、324,485 tokens。**不能据此把 v3 宣称为整体优化成功，也不能将角色数的变化归因于某篇论文。** 详见 [v3 实测报告](jev_rcta_adaptive_v3_20260924_report.md)。

诊断发现不同瓶颈：代码任务中正确步骤已被取回并检查，最终选择仍转为 unknown；另一个短任务的正确步骤因没有查询词重合而被词法筛选排除。后者本来能把全部原文放进预算，因此在 v3.1 中修复为完整原文路径。此前 v3 的代码已随运行目录归档；v3.1 采用独立协议与结果目录，不覆盖或混入六条对照结果。

当前 v3.1 是研究分支，v2 保留。短样本修复只做独立回归检查，不将该样本结果替换进 v3 的六条分数，也不把额外测试隐藏为首次运行。

## v3.1 独立回归与本轮用量

短样本 `vitabench__089` 的全部 10 步原文进入初始视图；第 8 步不再因缺少检索词而被过滤，并成为第一个检查的候选。最终点预测为第 8 步，与参考一致；角色仍为 unknown，严格核验未通过。根因题给第 8 步的概率为 0.48，核验仍不能确认错误来源与后续影响，因此不将点预测标为“证据已充分支持”。这是已知缺陷的一条回归结果，不是未见测试集上的准确率，也不能合并替换 v3 原六条结果。详见 [独立回归报告](jev_rcta_adaptive_v31_regression_20260924_report.md)。
