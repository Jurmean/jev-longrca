# JEV-RCTA 架构与可行性验证

日期：2026-09-21。状态：实现与离线验证完成，在线验证因 API 额度不足暂停。

## 实现范围

- 方法：`scripts/jev_rcta.py`，协议 `jev-rcta-choice-v1`，模型固定 `jev-1.13.0`。
- 入口：`scripts/evaluate_jev_rcta.py`，仅用 Python 标准库。
- 传输：`scripts/jev_rcta_client.py`，保存原始请求/响应，精确请求摘要匹配后恢复。
- 流程：分段和重叠上下文、原文证据卡、多候选比较、上游交接检索、五类关系判断、有界回溯、独立角色/根因选择。
- 推理函数只接收 history；人工角色、根因步骤、解释不进入模型。
- 原始 JEV/Laya 基线的推理代码与历史结果未改动。

这是 RCTA 启发的 Choice 架构，不是原论文方法的等价复现。证据卡为抽取式节选；关系分类为未验证假设，非因果证明。

对固定版本 Mini 200 条轨迹执行原文覆盖审计，共产生 2,229 个主分段，逐步骤重组后与原始文本完全一致。审计过程中 API 调用为 0。详见 `results/jev_rcta_audit/data_audit.json`。

上述测试使用本地模拟响应，只验证程序行为，不验证 JEV 语义判断能力。全量覆盖成立于初筛主分段；后续证据卡、邻接内容和最终证据仍有明确标记的截取。

## 结论与续跑条件

代码流程与额度停止机制具备离线测试支持，真实 API 端到端可行性及效果仍未验证。不能据此宣称该方法优于原 JEV 基线或原论文 RCTA。

当前停止标记会阻止同一输出目录的后续请求。待用户明确确认充值或提供新的 API 配置后，归档该标记，并使用原命令恢复五条最短样本测试；成功后再运行中位长度组。两组均通过后，才能据结果决定是否扩大评测。

```bash
python3 scripts/evaluate_jev_rcta.py --smoke --output results/jev_rcta_smoke
python3 scripts/evaluate_jev_rcta.py --pilot --output results/jev_rcta_pilot
```

配置冻结代码与数据摘要，变更方法或参数后必须改用新的输出目录。
